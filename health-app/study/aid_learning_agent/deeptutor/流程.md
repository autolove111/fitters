短期记忆就是 conversation_history——历史对话，它不在 system 消息里，而是作为独立的 user/assistant 消息插在 system 和当前问题之间：

短期记忆的特殊处理
历史对话不一定是原样传入，ContextBuilder 会压缩：


原始历史（可能很长）：
  user: "什么是极限？"
  assistant: "极限是当自变量趋近于某个值时..."
  user: "那导数呢？"
  assistant: "导数是函数在某一点的变化率..."
  user: "能举个例子吗？"
  assistant: "比如 f(x)=x²，在 x=2 处..."
  ...（可能有几十轮）

        ↓ ContextBuilder 压缩

压缩后传给 LLM：
  user: "[对话摘要] 用户在学习微积分基础，讨论了极限、导数的概念和例子..."
  user: "能再解释一下链式法则吗？"    ← 最近几轮保留原文
  assistant: "链式法则用于求复合函数的导数..."
  user: "解释傅里叶变换"              ← 当前问题
压缩规则：

模型上下文窗口的 35% 分给历史
其中 60% 给近期消息（原文保留）
40% 给旧消息（用 LLM 压缩成摘要）
压缩后的摘要存入 session，下次继续用
总结
记忆类型	在哪	内容	生命周期
长期记忆	system 消息内	用户画像、偏好、知识范围	跨会话持久
短期记忆	system 和当前问题之间的 user/assistant 消息	历史对话（可能被压缩）	当前会话内



工具调用的完整过程
用一个具体例子，一步一步走：

第 1 步：LLM 决定调工具
LLM 看到用户问「解释傅里叶变换」，它判断：这个问题知识库里可能有，我先检索一下。

LLM 的回复不是普通文字，而是带了一个 tool_calls 字段：


{
  "role": "assistant",
  "content": "``TOOL`` 我先从知识库检索傅里叶变换的定义。",
  "tool_calls": [
    {
      "id": "call_abc123",
      "type": "function",
      "function": {
        "name": "rag",
        "arguments": "{\"query\": \"傅里叶变换定义\", \"kb_name\": \"线性代数\"}"
      }
    }
  ]
}
注意：tool_calls 是 OpenAI API 的原生功能，不是 DeepTutor 发明的。LLM 输出的 JSON 里自带了「我要调哪个函数、传什么参数」。

第 2 步：系统收到 tool_calls，分发执行
DeepTutor 的 agentic loop 收到 LLM 回复后：


# agentic loop 里的逻辑（简化版）
response = await call_llm(messages)

if response.tool_calls:  # LLM 想调工具
    for tool_call in response.tool_calls:
        name = tool_call.function.name          # "rag"
        args = json.loads(tool_call.function.arguments)  # {"query": "...", "kb_name": "..."}
        
        # 去 ToolRegistry 找到 rag 工具，执行它
        result = await tool_registry.execute(name, **args)
第 3 步：rag 工具执行

class RAGTool(BaseTool):
    async def execute(self, query, kb_name, **kwargs):
        # 1. 找到知识库的向量索引
        # 2. 把 query 做 embedding
        # 3. 在向量索引里找最相似的段落
        # 4. 返回结果
        
        result = await rag_search(query=query, kb_name=kb_name)
        return ToolResult(content=result["answer"])
实际调用的是 services/rag/ 里的向量检索服务（基于 LlamaIndex）：


用户 query: "傅里叶变换定义"
        ↓
embedding 模型把 query 转成向量: [0.12, -0.34, 0.56, ...]
        ↓
在知识库的向量索引里找最相似的段落（余弦相似度）
        ↓
返回匹配度最高的 3-5 个段落

关键点
问题	答案
LLM 怎么知道可以调工具？	system prompt 里的 {tool_list} 告诉它有哪些工具可用
LLM 怎么决定调哪个？	它自己判断——prompt 里的 when_to_use 给了指导，但最终是 LLM 的决策
工具结果怎么传回 LLM？	作为 role=tool 消息追加到 messages 数组，再次调 LLM
为什么要再次调 LLM？	因为 LLM 需要阅读工具结果才能生成最终答案
一次对话能调几次工具？	最多 20 轮（configurable），每轮可以调多个工具并行执行
最简化的代码流程

async def agentic_loop(messages, tools):
    while True:
        # 1. 调 LLM
        response = await openai.chat(messages, tools=tools)
        
        # 2. 如果 LLM 想调工具
        if response.tool_calls:
            # 3. 执行工具，拿到结果
            results = await execute_tools(response.tool_calls)
            
            # 4. 把工具结果塞进 messages
            messages.append(response)        # assistant 的 tool_calls
            messages.extend(results)         # tool 的执行结果
            
            # 5. 回到第 1 步，再次调 LLM
            continue
        
        # 6. 如果 LLM 说 FINISH，退出循环
        if "FINISH" in response.content:
            return response.content
就这么简单：调 LLM → 有工具调用就执行 → 结果塞回去 → 再调 LLM → 直到 FINISH。
