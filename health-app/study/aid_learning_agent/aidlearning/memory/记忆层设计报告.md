# AidLearning 记忆层设计报告

## 1. 架构总览

AidLearning 采用四层记忆架构，参照 Hermes 设计理念，结合自身教育场景特点进行实现。

```
┌─────────────────────────────────────────────────────────────────┐
│                        LLM 每轮看到的内容                        │
│                                                                 │
│  system prompt = 基础 prompt                                    │
│                + 长期记忆（按相关性+衰减检索）                     │
│                + 匹配的技能卡（程序性记忆）                        │
│                                                                 │
│  messages = 短期记忆（buffer 滑动窗口 + 压缩摘要）                │
│                                                                 │
│  tools = [session_search, read_memory, write_memory, ...]       │
└─────────────────────────────────────────────────────────────────┘
```

### 四层对应关系

| 层级 | 存储介质 | 内容 | 核心目的 |
|------|---------|------|---------|
| **短期记忆** | 内存 ConversationBuffer | 当前会话的滑动窗口 + 压缩摘要 | 保证当前对话的流畅与连贯 |
| **中期记忆** | SQLite messages 表 + FTS5 | 完整的任务日志和操作记录 | 跨会话查询，回忆"上周做过什么" |
| **长期记忆** | Markdown L2/L3 文件 | 精炼的用户画像和学习事实 | 维持核心人格和偏好，低成本常驻上下文 |
| **程序性记忆** | workspace/skills/*.md | 可复用的操作方法 | 教会 AI"怎么做"而非"是什么" |

## 2. 短期记忆（Short-term Memory）

### 2.1 设计目标

- 提供当前会话的上下文窗口
- 自动压缩旧消息，控制 token 用量
- 进程重启后可恢复

### 2.2 核心组件

**ConversationBuffer**（`memory/short_term/conversation_buffer.py`）

```python
class ConversationBuffer:
    token_budget: int = 500          # token 预算上限
    summary: str                     # 压缩摘要
    summary_tokens: int              # 摘要 token 数
    _messages: list[_Message]        # 滑动窗口内的消息
    _compressed_count: int           # 已压缩消息数
```

**BufferManager**（`memory/short_term/buffer_manager.py`）

```python
class BufferManager:
    _buffers: dict[str, ConversationBuffer]  # 每个 session 一个 buffer
    _initialized: set[str]                   # 已从 SQLite 加载的 session
```

### 2.3 滑动窗口机制

```
token 预算: 500 tokens

用户发消息 → buffer.append("user", content)  → maybe_compress()
AI 回复    → buffer.append("assistant", content) → maybe_compress() → flush()

压缩逻辑:
  总 token > 500 → 压缩旧消息
  目标: 压缩到 80%（400 tokens）→ 避免每轮都压缩
  压缩方式: LLM 摘要（保留用户目标、约束、决策、未解决问题）
```

### 2.4 持久化与恢复

```
写入:
  flush() → 消息写入 messages 表
          → summary 写入 sessions 表
          → 窗口状态写入 buffer_state 表

恢复:
  get_or_create(session_id)
    → load_buffer_state(session_id)
    → 恢复 summary + 窗口消息 ID
    → 只加载窗口内的消息（不加载全部）
```

### 2.5 关键文件

| 文件 | 职责 |
|------|------|
| `memory/short_term/conversation_buffer.py` | 滑动窗口 + 压缩逻辑 |
| `memory/short_term/buffer_manager.py` | 全局 buffer 管理 + SQLite 持久化 |
| `memory/short_term/context_builder.py` | 兼容层（保留但不再被 turn_runtime 使用） |

## 3. 中期记忆（Mid-term Memory）

### 3.1 设计目标

- 完整记录所有交互历史
- 支持全文搜索（FTS5）
- 作为长期记忆的数据来源
- 跨会话查询能力

### 3.2 存储结构

```sql
-- 消息表（已有）
CREATE TABLE messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL,
    role TEXT NOT NULL,
    content TEXT NOT NULL,
    capability TEXT,
    events_json TEXT,
    attachments_json TEXT,
    metadata_json TEXT,
    created_at REAL NOT NULL,
    parent_message_id INTEGER
);

-- FTS5 全文索引
CREATE VIRTUAL TABLE messages_fts USING fts5(content, content=messages, content_rowid=id);

-- buffer 状态表
CREATE TABLE buffer_state (
    session_id TEXT PRIMARY KEY,
    summary TEXT,
    summary_tokens INTEGER,
    compressed_count INTEGER,
    window_message_ids TEXT,  -- JSON 数组
    updated_at REAL
);
```

### 3.3 搜索能力

**FTS5 全文搜索**（`session_search` 工具）：

```python
# LLM 调用示例
session_search(query="极限", days=7)    # 搜最近 7 天
session_search(query="微积分")           # 搜全部
session_search(query="agent", session_id="abc123")  # 限定会话
```

**降级策略**：FTS5 不可用时自动降级为 LIKE 搜索。

### 3.4 关键文件

| 文件 | 职责 |
|------|------|
| `services/session/sqlite_store.py` | SQLite 操作 + FTS5 索引 + buffer_state 表 |
| `memory/mid_term/search.py` | 统一检索管线（FTS5 + 长期记忆关键词） |
| `tools/builtin/__init__.py` | `SessionSearchTool` 工具实现 |

## 4. 长期记忆（Long-term Memory）

### 4.1 设计目标

- 从中期记忆中提炼精炼事实
- 按交互面分类存储
- 支持时间衰减
- 低 token 成本常驻上下文

### 4.2 两层结构

```
memory/
  L2/                    ← 单交互面摘要（2 个文件）
    chat.md              ← 从 chat/notebook/quiz/book/tutorbot/cowriter 提炼
    kb.md                ← 从 kb 提炼

  L3/                    ← 跨交互面综合（4 个文件）
    recent.md            ← 近期学习摘要
    profile.md           ← 用户画像
    scope.md             ← 知识范围
    preferences.md       ← 用户偏好
```

### 4.3 L2 路由规则

```
7 个 surface 的消息 → 2 个 L2 文件

chat     ─┐
notebook ─┤
quiz     ─┼→ L2/chat.md
book     ─┤
tutorbot ─┤
cowriter ─┘

kb       ───→ L2/kb.md
```

### 4.4 文档格式

```markdown
# Chat memory

## Topics
- 学习了极限的ε-δ定义 [^1] <!--m_01HZK4...-->
- 学习了导数的几何意义 [^2] <!--m_01HZK5...-->
<!--meta:created=1717200000;accessed=1717200000;count=3;imp=0.7-->

---

[^1]: msg:15
[^2]: msg:19
```

### 4.5 衰减机制

```python
def compute_decay_score(created_at, last_accessed, access_count, importance):
    base_decay = 2^(-age_days / 90)           # 权重 0.5，半衰期 90 天
    recency    = 2^(-recency_days / 180)       # 权重 0.2
    frequency  = 1 - 1/(1 + 0.1 * count)       # 权重 0.1
    importance = importance                     # 权重 0.2
    return 0.5*base + 0.2*recency + 0.1*frequency + 0.2*importance
```

效果：
- 今天创建：score ≈ 1.0
- 90 天前、从未访问：score ≈ 0.5
- 6 个月前、从未访问：score ≈ 0.15
- score < 0.05 → 被 cleanup 清理

### 4.6 关键文件

| 文件 | 职责 |
|------|------|
| `memory/long_term/document.py` | Markdown 文档模型 + 序列化 |
| `memory/long_term/ops.py` | 原子增删改操作 |
| `memory/long_term/decay.py` | 衰减评分函数 |
| `memory/store.py` | MemoryStore 门面 |
| `memory/consolidator/modes/update.py` | 整合器（消息 → L2/L3） |
| `memory/consolidator/modes/cleanup.py` | 衰减清理 |

## 5. 程序性记忆（Procedural Memory）

### 5.1 设计目标

- 从重复操作中自动提取可复用技能
- 用户手写技能卡
- LLM 自动匹配相关技能

### 5.2 技能卡格式

```markdown
---
name: data-analysis
description: 处理 CSV 数据分析任务
triggers: [csv, 数据分析, dataframe, pandas]
tags: [tool]
---

处理 CSV 数据时，按以下步骤操作：
1. 读取文件，检查列名和数据类型
2. 处理缺失值
3. 进行描述性统计
4. 生成可视化图表
```

### 5.3 自动匹配

```python
# 关键词匹配（无 LLM）
score = 0
for trig in triggers:
    if trig in user_message:
        score += 3  # trigger 命中 +3
for token in description_tokens:
    if token in user_message:
        score += 1  # 描述词命中 +1
```

## 6. 层级转化流程

### 6.1 短期 → 中期（自动，每条消息）

```
用户发消息 → buffer.append()
AI 回复    → buffer.append()
           → flush() → messages 表写入
           → FTS5 自动索引
```

**触发条件**：每条消息写入时自动发生。

### 6.2 中期 → 长期（手动/自动触发整合器）

```
messages 表 → 整合器 run_update("L2", "chat")
  → get_all_messages(exclude_ids=已处理ID)
  → render_messages_for_concat() 格式化
  → 分块 → LLM 提取事实
  → 写入 L2/chat.md
  → 更新 meta.json（seen_message_ids）

L2 文档 → 整合器 run_update("L3", "profile")
  → LLM 综合提炼
  → 写入 L3/profile.md
```

**触发条件**：
- 手动：Memory workbench 点 "Update"
- 自动：待实现（可配置定期触发）

### 6.3 长期 → system prompt（每轮自动注入）

```
用户发消息
  → retrieve_memory(query=用户消息)
    → FTS5 搜索中期记忆（messages 表）
    → 关键词匹配长期记忆（L2/L3 Markdown）
    → 合并去重 → 按 final_score 排序
    → 格式化为 markdown
  → 注入 system prompt
```

### 6.4 LLM 主动写入长期记忆

```
用户说"以后多举例子"
  → LLM 调用 write_memory(op="add", text="多举例子")
  → 直接写入 L3/preferences.md
  → 同时写入 L1 追踪事件（溯源用）
```

## 7. 上下文分配与 Prompt 构建

### 7.1 每轮对话的上下文组装

```
turn_runtime._run_turn()
  │
  ├─ ① 短期记忆：buffer.get_context()
  │     → [{"role":"system","content":"摘要..."}, 最近消息...]
  │
  ├─ ② 中期+长期记忆：memory_store.retrieve_memory(query)
  │     → "## Relevant Memory\n- 用户偏好中文讲解..."
  │
  ├─ ③ 程序性记忆：skill_service.auto_select(message)
  │     → "## Active Skills\n### data-analysis\n..."
  │
  └─ ④ 来源清单：build_inventory()
        → "## Attached Sources\n- [1] 教材PDF..."
```

### 7.2 最终 LLM 消息结构

```
┌─ system message ──────────────────────────────────────┐
│ 基础 prompt + 工具提示 + KB 注释 + 语言指令            │
│ ---                                                   │
│ ## Relevant Memory                                    │
│ - 用户偏好中文讲解多举例 [chat]                        │
│ - 上周学了极限定义 [notebook]                          │
│ ---                                                   │
│ ## Active Skills                                      │
│ ### math-tutor                                        │
│ 讲数学时：先给直觉，再给定义，最后举例                  │
│ ---                                                   │
│ ## Attached Sources                                   │
│ - [1] 线性代数教材.pdf                                 │
├─ conversation history ────────────────────────────────┤
│ system: 用户从零学微积分，已掌握极限和导数...           │
│ user: 什么是极限                                      │
│ assistant: 极限描述的是...                             │
├─ current message ─────────────────────────────────────┤
│ user: 用中文讲讲积分                                   │
└───────────────────────────────────────────────────────┘
```

## 12. 已知限制与后续优化

| 限制 | 说明 | 优化方向 |
|------|------|---------|
| FTS5 兼容性 | 部分 SQLite 构建不含 FTS5 | 已实现 LIKE 降级 |
| 整合器手动触发 | L2/L3 需手动点 Update | 可配置自动触发（消息数阈值/定时） |
| 程序性记忆未接入 | 自动提取框架已实现但未调用 | 接入对话流程，成功操作后自动提取 |
| 长期记忆关键词匹配 | L2/L3 搜索用关键词而非语义 | 可加 embedding 索引 |
| buffer 压缩依赖 LLM | 压缩需要 LLM 调用 | 可用规则压缩作为降级 |
