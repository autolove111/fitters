第四阶段：工具注册与约束
4.1 工具 Schema 注入 LLM

tool_schemas = _build_llm_tool_schemas(enabled_tools, context)
每个工具转为 OpenAI function-calling 格式，并注入运行时约束：


{
  "type": "function",
  "function": {
    "name": "rag",
    "parameters": {
      "properties": {
        "query": {"type": "string"},
        "kb_name": {
          "type": "string",
          "enum": ["线性代数"]    // ← 约束：只能用附加的 KB
        }
      },
      "additionalProperties": false
    }
  }
}
这防止 LLM 幻觉出不存在的 KB 名称或 source ID。

第五阶段：Agentic 循环

run_agentic_loop(messages, tool_schemas, ...)
每轮迭代：


LLM 调用 (streaming)
  │
  ├─ FINISH → 输出最终回复，退出循环
  │
  ├─ TOOL → 并行执行工具调用（最多 N 个）
  │    ├─ rag("什么是极限", kb_name="线性代数")
  │    ├─ read_memory(query="极限")
  │    └─ 结果追加为 role=tool 消息
  │
  ├─ THINK → 内部推理，继续循环
  │
  └─ PAUSE → 暂停等待用户回复（ask_user 工具）
上下文保护：如果消息超过模型上下文窗口的 90%，最旧的 role=tool 内容被裁剪为 [snip]。

迭代上限：最多 20 轮，超限后强制 FINISH。
